# Governed Trackables

Identify the existing domain writer, subject, purpose and exact private scope.
Separate tracking lifecycle, domain fulfillment, occurrence result, evidence
quality and attention. Recording a daily practice does not finish the practice;
pausing tracking does not abandon a goal. Missing evidence is not zero or failure.

Check the installed `atelier trackable` interface and supported profile before
promising behavior. The reference profile supports daily recurring practice,
one-off milestones and unscheduled qualitative observations. It does not provide
arbitrary recurrence, quantitative metrics or a developmental score. Preserve
native profiles and report unsupported mappings rather than converting meaning.

Release and pin a validated definition. Preview through the same reducer that the
runtime uses. Adopt an exact revision with an effective instant; do not silently
change existing instances when authoring changes. Preserve timezone, local-day
identity and the definition applicable to late evidence.

Within the user's existing authority, use typed commands with request identity
and expected revision. Preserve subject, recorder, source event and assistance
separately. Retry the same command after a lost reply; do not create another
completion. Reconcile manual and session reports of one occurrence. Corrections
retain source history and cause affected fulfillment evidence to be reconsidered.

Verify durable readback and refreshed presentation. Show unobserved, skipped,
waived, partial and disputed states honestly. A proposed mutation is not saved.
Companion can present the same view; Witness is optional and cannot maintain a
second progress truth or infer independent ability from assisted completion.

Use the local private store only as the standalone reference adapter. Product
hosts retain authenticated persistence, evidence validation and access control.
Do not implicitly export personal history, enable reminders or broaden observation.
