# Practical Judgment

Clarify the purpose, particulars, affected people and consequential choice.
Preserve the person's contribution, competing interpretations, tacit distinctions,
contrasting cases and warranted exceptions. Deliberation may end in a fitting
action, a deferred choice or a question; it need not yield a general rule.

Inspect existing instructions, capabilities and domain owners before formalizing
practice. Reuse them. Inquiry investigates uncertainty; Knowledge Stewardship
curates evidence and applicability; Skill Steward governs reusable skill bindings.
Companion remains the host's conversational role. Witness reflection or coaching
is optional and must not create an implicit personal monitoring program.

## Cases, decisions and learning

Use the installed `@mnstry/atelier/judgment` case contract when a durable practical
case is useful. Retain purpose, alternatives, dissent, cultivation exercises,
consequences and reconsideration conditions. Do not translate practical judgment
into a universal score or call software conformance wisdom.

Import ADRs with native repository identity and exact source bytes. Keep decision
status, implementation and evidence currency separate. Follow the repository's
native numbering, review and supersession process; never invent an approval.

For an accepted reusable lesson, use `atelier learn`: capture the actual evidence,
propose scoped meaning and exceptions, record the real disposition, then activate
an exact version for its intended harness. Capability-event metadata may enter
through `capabilityEventToLearningInput`; it is not a user quotation or causal
proof. Never relabel a failed tool as deficient user ability.

## Land accepted practice

Name each destination and the behavior it should change. An instruction is
guidance; a deterministic rule needs an actual validator or operation consumer.
Changes to skills use exact Capability Stewardship packages and independent
repository adoption. Code, workflows and interfaces use the owning build process.

For the supported scoped instruction profile, run `atelier practice plan` using
JSON stdin in the intended Git repository. It names workspaceId, scope, harnessId,
lessonId, target (AGENTS.md or CLAUDE.md), slot and mode. Inspect the concrete text
and current base. Within existing user authority, apply with the returned digest
as confirm. Preserve adjacent text and ownership. A stale plan or unmanaged slot
requires reconciliation, not a force option. `practice status` exposes pending
writes; `practice recover` takes the exact pending plan digest.

A next task must actually receive the adopted version. A host can call
`practice context` with target, slot, session, scope and harnessId to obtain current
guidance and a delivery receipt. Report this as returned context, not proof of
obedience. Exercise an applicable case and a meaningful counterexample; assess
the observed outcome separately from installation and lasting benefit.

Withdrawal excludes later context API calls. Existing instruction files still
require an explicit retirement plan; direct file readers do not acquire automatic
freshness checks. Preserve history and local edits across correction or recovery.
Different repositories can independently adopt, defer, customize or retire.

If a tool or profile is unavailable, prepare the exact proposed artifact and
report the unsupported binding. Do not claim execution. Do not export private
learning, publish capabilities or send messages merely because a lesson exists.
