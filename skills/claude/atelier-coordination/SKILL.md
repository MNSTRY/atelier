# Portable Coordination

Name the outcome, integration owner, scope, exact candidate or artifact, receiving
need, next action and forecast. Discover the existing native source of each fact.
Reuse Build, Harness and repository coordination records rather than starting a
parallel approval system. Local operation does not require a Fabric service.

Use the installed Coordination contracts for bounded outcome, dependency,
directive, disposition and recovery observations. Preserve source references,
observation time and expiry. Missing, stale, changed or future-dated observations
cannot become fresh merely because a dashboard can render them. Detect dependency
cycles and keep receiving acceptance separate from producer source completion.

Bind each gate to its candidate. Tests, independent review, CI, merge, deployment,
activation and recipient acceptance retain separate evidence and authority.
A reported waiver is not a passed test. A receipt reference is not authenticated
verification. Use native verification where acceptance depends on that receipt.

Directives preserve target, scope, expiry, supersession and proposed/sent/read/
applied/verified distinctions. Do not infer a later stage from an earlier report.
A directive or skill grants no messaging, execution or repository adoption power.
Act only within existing user authority and the destination's actual contracts.

For interruption or retirement, preserve exact prior state, recovery evidence and
successor identity. Do not wake another owner, overwrite dirty work or delete
uncertain journals to make a view appear settled. Report the smallest concrete
receiving dependency and keep unrelated admitted work moving.
