# Portable Coordination and native authority

Coordination connects outcomes, owners, scopes, dependencies, directives,
delivery, recovery and successors. It reads domain truth through typed references.
A portfolio view cannot approve a change or manufacture a receiving receipt.

`@mnstry/atelier/coordination` validates bounded outcome, dependency, directive,
disposition and recovery observations. `coordinationView` projects them against
an explicit time and freshness window. Missing, expired, future-dated, changed or
ambiguous inputs remain visible. Producer references include repository identity
and exact record digest. Dependency cycles are reported and block that chain.

A receiver's reported receipt and acceptance remain separate from the producer's
source gates. Gate reports bind an exact candidate. Passed, waived and pending
retain their meaning; a waiver is not a passed test. Native receipt references
are retained but not authenticated by this library. Every view exposes this
limit and leaves completion and execution authority unestablished.

Directives retain target, scope, expiry and supersession. Dispositions report
proposed, sent, read, applied, verified or declined independently. A sent report
does not imply reading or application; a record saying verified is still a
native-owner report until that owner's verification is exercised. Recipient,
repository, scope and current directive pins qualify applicability. Recovery
retains prior/source and successor references without retiring a native task.

`coordinatedBuild` includes the existing Build readiness result unchanged. Its
native histories, independent gates and snapshot verification remain
responsible for their own truth. Neither a portfolio observation nor a local
projection can waive a Build blocker.

## Fabric capability placement

| Capability | Open-root disposition | Native responsibility |
| --- | --- | --- |
| Identity/provenance | Reuse domain references and immutable byte digests | Authentication and trusted custody |
| Outcomes/owners/priorities/scope | Adapt through typed Coordination observations | Actual ownership and priority decisions |
| Dependencies/handoffs | Reuse Harness verification; add cross-repository dependency/cycle views | Trusted snapshot acquisition and receiving receipt verification |
| Directives/dispositions | Add scoped versioned observations and distinct stages | Sending, receiving, wakeups and authenticated acknowledgements |
| Delivery/gates | Reuse Build candidate, attempt, decision and gate records | Commands, CI, review and deployment |
| ADRs | Practical Judgment native-byte adapter and decision record | Repository numbering, authority and acceptance |
| Practice/context | Learning lifecycle and scoped instruction adoption | Host context admission and observed behavior |
| Ingestion/knowledge | One Intake source lineage, bounded ingestion, Knowledge review and context | Source rights, domain meaning and external processing |
| Capability adoption | Capability releases, independent repository plans, Skill Steward and feedback bridge | Publisher trust, host loading and native use |
| Recovery/retirement | Existing journal recovery plus retained successor observations | Distributed leases, backup, retention and deletion |
| Portfolio/observability | Bounded pure views with coverage and freshness | Collectors, native dashboards and services |
| Improvement | Inquiry, situated cases, learning proposal/evaluation/disposition | Model/provider operation and consequential judgments |

Local operation requires no Fabric account or service. Hosted collection,
distributed coordination and commercial interfaces may implement these contracts
while retaining their own authority. A complete operated Fabric integration needs
an exact native adapter and receiving proof; the portable views do not claim it.
