# Additive integration reference

The [additive module sources](../../src/knowledge/participatory/index.mjs) accept the host's already received APIs. They create no editor, store, parser, accepted ontology or application route. The owning package must bind its supported public export before offering these functions to installed callers. This reference supplies no unsupported deep-import instruction.

```js
// Host composition after native/public receiving; the release owns the import.
const guided = createGuidedContribution({
  adapter: existingSourceBoundContributionAdapter,
  caller: existingNativeKnowledgeHealthCaller,
  same: existingCanonicalEquality,
});
const prepared = guided.prepareChoice({
  joined: freshValidatedFindingJoin,
  editorState: currentNativeEditorState,
  contributionId: hostContributionId,
  choiceId: hostChoiceId,
  originalWords: exactParticipantWords,
  interpretation: separateProposedInterpretation,
  outcome: explicitParticipantOutcome,
  participantChoice: actualParticipantChoice,
});
```

The result is `chosen-not-retained`. The native caller's `retainDisposition` performs the existing two append steps and independent readbacks. Bind its `writeContribution`, `readContribution`, `writeDisposition` and `lookupDisposition` to the current native actor/source boundary. `checkDisposition` resolves an unknown result by lookup; `retryDisposition` requires an explicit retry with the same full record after checked absence. The adapter verifies source, saved passage and field; the owning host still checks currency and permission at effects.

`exampleRevision({joined,contribution,proposalId,changeId,decisionId})` creates only the invented workshop's proposed supporting-array change. It refuses another source, field or directed relationship. The output contains a native proposal and `selected-not-applied` intent. Receive the actual contribution/proposal, show the native preview, and obtain the participant's explicit selection before native `recordDecision` and draft `apply-selection`. Preparing an example proposal does not authorize either write. Native provenance rules still govern assistant responses; this proposal is labeled `invented-example-proposal`.

`guidanceFor(stage)` supplies concise copy and an existing-host navigation intent. `createGuidanceCue({React,Button})` renders that cue with the existing Runtime Button. It creates no input or editor. The host selects the cue from its validated state and decides whether a corresponding action is available; the cue grants no effect permission. Keep one stable cue ID, the existing editor key and the normal return-focus path. `onAction` requests navigation/check intent only; pending save has no action. Do not infer successful retention, source application or reassessment by advancing a step number.

For another repository, bind its real declared sources and supported check, field, saved occurrence, actor/store/head and normal source-writer route. Reassess after any source or evidence change. An unresolved mapping remains unsupported; do not match titles, translate old ranges, infer an ownership grant or reuse the workshop change generator on real material.
