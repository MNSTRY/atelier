# Support and recovery

| Capability | What this supplier establishes | What the installed release must establish |
| --- | --- | --- |
| Workshop source and check | Native graph, plan, context and question evaluation on these exact invented sources | Installed assessment entry, evidence read-set and current source binding |
| Original words and choices | Actual native full-reference disposition APIs retain all four choices and separate interpretation in a disposable ledger | Actor/source/head checks at the host boundary and participant-visible controls |
| Draft preview/application | Actual native selected decision, preview, apply, save and reopen in disposable state | Installed Review/focus/undo flow and current effect permissions |
| Source change/reassessment | Owned disposable source edit, exact readback and same-rule reassessment | The real owning repository edit route and fresh expected evidence |
| Recovery | Original-ID native lookup after a withheld response, with no second write | Installed pending-intent/scratch recovery across browser and service restart |
| Accessibility | Cue structure, received Button role/focus and synthesized Enter/Space activation, disabled refusal and editor preservation in DOM qualification | Real keyboard navigation/focus return, screen reader, zoom, IME and browser checks |

Qualification uses Node 22.18.0. The installed package's declared engine range governs other versions. A local same-machine authoring host supplies its own actor binding and owning routes; this supplier does not add hosted authentication or grant access to another repository. Use only public invented material in the example copy. No hosted account or provider call is needed for this guided supplier's supported case.

| Visible state | Keep | Next step |
| --- | --- | --- |
| No applicable finding | Your writing and any plain note | Select supported example material or ask which input is supported. |
| Saving/checking | Original operation and newer words | Wait; verify the exact saved revision. Do not start another write. |
| Words saved, choice unconfirmed | Original contribution and complete choice record | Check original choice. Lookup reads only. |
| Lookup proves choice absent | The same choice ID and identical complete record | Explicitly retry only if the host offers its fenced original-choice action. |
| Source/head changed | Human words, old source reference and history | Read current source/head; choose whether to attach a fresh contribution. |
| Draft saved, source unchanged | Selected draft and proposal | Ask its actual source owner to review the change. |
| Source applied, old expected evidence | Source readback and old result | Refresh expected evidence through the owner and reassess; keep both results. |

Never solve an unknown save by deleting history, changing the operation ID, dispatching an assistant, or restarting someone else's editor. If lookup is unavailable, remain unconfirmed and preserve the intent.

Use this checklist during the installed rehearsal:

- Tab/Shift-Tab reaches evidence, contribution input, choice controls, Review and return controls in an understandable order; focus is visible and no trap occurs.
- Enter/Space activates each button once. A disabled control cannot write. Choice labels expose the chosen state and a choice is not preselected as human consent.
- The source evidence and proposed interpretation have readable labels. Status changes are announced without moving focus or replacing the editor.
- Escape/return uses the host's normal path back to the original editor and caret. Native undo/redo, selection and composing text remain intact.
- Save during a later edit acknowledges only the saved revision; the newer text remains visible and unsaved. Unknown choice/application exposes a read-only check before retry.
- Reopen/reload/service restart recovers exact words, interpretation, choice and pending identity. An old note is labeled historical after source/head changes.
- Zoom, narrow layout and screen-reader reading retain the evidence/choice distinction. Test the release's actual supported browser and IME; DOM observations alone do not establish these.
