# Facilitator run sheet

Use the exact supported release and one new disposable workshop copy per participant. The kit's target session is Thursday 8 October 2026; rehearse the installed version on Wednesday 7 October. Those dates do not prove publication or participant acceptance.

Before the session, obtain the release owner's verified version and guided entry. Install that exact version using the package's tested quickstart, check its documented Node/Git/browser prerequisites, and rehearse the whole [exercise](exercise.md) from a clean copy without private paths, developer imports or environment overrides. Do not start until the public launch, copy/open, contribution, interpretation, Review, source-owner correction, readback/reopen and reassessment steps are available. Keep any genuine missing step visible.

| Time | Invitation | Observe without answering for the participant |
| --- | --- | --- |
| 0–3 minutes | “Read these two sources. What do you think their connection is?” | Can they distinguish source words from graph projection? |
| 3–6 | “What exactly does this finding show?” | Do they find the `[]` evidence and understand the limited relationship check? |
| 6–11 | “Add your own words. How would you like them understood?” | Original words, separate interpretation, an explicit choice, and optionality. |
| 11–15 | “Would you keep the proposed declaration change?” | Preview before effect, ability to disagree or return, selected draft readback. |
| 15–20 | “What has changed after the source owner acts and the check runs again?” | Source versus draft, reopened text, current evidence and remaining judgment. |
| 20–25 | “What was useful, confusing or missing?” | Record the participant's actual words and any unanswered question. |

Offer the participant the source-owner role only for their own disposable copy. Explain what the ordinary source write will change before granting that role. Keep source ownership and participant judgment distinct even when one person performs both.

For a recovery exercise, use the host's documented disposable failure rehearsal. If it has no supported rehearsal, discuss the visible unconfirmed state without disconnecting an unknown service. A pending choice is checked under its original identity; it is not submitted as a new note. Do not run a provider to fill a gap, alter a participant's words, or reset the example's history.

Observe keyboard access and the [checklist](support.md). If a step fails, preserve the words and exact pending intent, record the visible state and reproduction steps, then use the normal support route. Finishing a scripted exercise is not evidence that the participant found it useful.
