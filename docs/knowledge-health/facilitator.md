# Facilitator run sheet

Use the exact supported release and one new disposable workshop copy per
participant. Record the package version, integrity and host used for rehearsal.

Before the session, install the selected version using the
[public workshop quickstart](quickstart.md), check its documented
Node/Git/browser prerequisites, and rehearse the flow from a clean copy. Verify
original words, separate interpretation and the explicit four-choice response
through ordinary saved drafts. Review saves a separately selected declaration;
the retained handoff is a copy-only proposal. Canonical source correction stays
with the source owner. Keep any missing or unqualified step visible.

| Time | Invitation | Observe without answering for the participant |
| --- | --- | --- |
| 0–3 minutes | “Read these two sources. What do you think their connection is?” | Can they distinguish source words from graph projection? |
| 3–6 | “What exactly does this finding show?” | Do they find the `[]` evidence and understand the limited relationship check? |
| 6–11 | “Add your own words. How would you like them understood?” | Original words, separate interpretation, an explicit choice, and optionality. |
| 11–15 | “Would you keep the proposed declaration change?” | Preview before effect, ability to disagree or return, selected draft readback. |
| 15–20 | “What has changed after the source owner acts and the check runs again?” | Source versus draft, reopened text, current evidence and remaining judgment. |
| 20–25 | “What was useful, confusing or missing?” | Record the participant's actual words and any unanswered question. |

Offer the participant the source-owner role only for their own disposable copy. Explain what the ordinary source write will change before granting that role. Keep source ownership and participant judgment distinct even when one person performs both.

For a recovery exercise, use the host's documented disposable failure rehearsal. If it has no supported rehearsal, discuss the visible unconfirmed state without disconnecting an unknown service. A pending request is checked under its original identity; it is not submitted as a new note. Do not run a provider to fill a gap, alter a participant's words, or reset the example's history.

Observe actual keyboard access, focus return, input-method behavior and recovery
in the receiving browser. If a step fails, preserve the words and exact pending
intent, record the visible state and reproduction steps, then use the normal
support route. Saved drafts do not establish native typed finding disposition,
authenticated approval or participant usefulness.
