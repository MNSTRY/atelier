# Participant response and separate Review

This public workshop uses the existing local Knowledge editor and ordinary coauthor drafts. Its author label is locally asserted. Saved drafts and proposal retention do not establish native finding disposition, authentication, semantic support, release readiness or human acceptance.

1. Start Workshop against the current `workshop-readiness` finding. Open its captured evidence, source declaration, anchor and finding fingerprints.
2. Record your original words, then save and continue. The consumer preserves lossless wording within 512 UTF-8 bytes. Original words cannot be replaced through Propose.
3. Record a separate optional interpretation, then save and continue. Leaving it blank records an explicitly empty interpretation. Proposed interpretation requires Confirm or Keep original wording before saving.
4. Choose Note, Perspective, Disagreement or Pause, then save and continue. Perspective retains the existing `perspective-only` value. Pause is a response choice; the session Pause control remains a separate navigation action.
5. Read the original contribution and choice event IDs, descriptor/event-history readback and immutable saved-value readback. A save request ID identifies the save receipt and differs from the original answer ID. An unsaved choice remains unconfirmed.
6. Review displays the current `[]` declaration and proposed `["devday:workshop"]` declaration. Return removes the preview and makes no request. Selecting the draft starts a separate linked Review session. Record selected draft, save it, continue, then reload or reopen the same session from history before preparing the handoff.
7. The copy-only source-owner handoff retains original words, optional interpretation, four-choice meaning, original contribution/choice IDs, contributor session, selected save receipt, source/anchor/read set and all six finding fingerprints. Foundation owns durable proposal retention and original-identity lookup in its existing sidecar/proposals implementation. That owner work remains prospective until applied and qualified.
8. The source owner checks the bound source digest and exact before/after UTF-8 declaration, edits the exact declaration through the ordinary repository route, reads it back, refreshes expected evidence and reruns the same assessment/question. Keep the earlier finding, contribution and selected draft as history. Automated Obsidian/frontmatter apply remains separate and keeps its refusals.

## Recovery and storage meaning

Retry first looks up the original request. Observed returns the retained result; not-found permits the same complete event intent to retry; unknown keeps the original intent without appending. A Review start is looked up as `kg-<original request UUID>`, independently of its contributor session ID. No successor UUID is generated during retry. Missing descriptors, ledger custody or immutable values remain unknown/unavailable.

The existing draft engine requires nonempty text. This consumer stores optional interpretation as the inert JSON text `{ "text": "..." }`, including the empty string. The editor and history decode it for display. Its save receipt's value digest binds the encoded text; it does not claim to bind the decoded string. Existing draft schema, event ledger, save/recovery rules and values directory remain authoritative.

`readSavedFields` reads the existing verified event chain and existing immutable values under the existing operation lock. It refuses redirected, missing or changed values and never reconstructs them. Reopen requires both owning readbacks to agree. Earlier descriptors without the participant profile marker retain their legacy revision history; new sessions use four responses and a separate Review.
