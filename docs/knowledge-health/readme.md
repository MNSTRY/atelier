# A workshop checklist

Start with the [public workshop quickstart](quickstart.md). It uses
the existing Knowledge host, ordinary private drafts and a copy-only
source-owner handoff. Choose a pinned package version that includes this profile
and rehearse that exact installation before a participant session.

Try one small Knowledge Health journey with two invented sources: a checklist and a proposed community workshop. The plan expects the checklist to support consideration of the workshop. Its declaration currently contains `supports: []`.

The check can show this missing relationship. It cannot decide whether the workshop is ready or whether that relationship is useful. You bring that judgment.

Use the [participant response guide](participant-response.md) or the
[facilitator run sheet](facilitator.md). All material is public and invented.
Work on your own disposable copy of
[the example](../../fixtures/knowledge-health/workshop/README.md).

The separate [assessment exercise](assessment/quickstart.md) uses an editor and
the assessment API with the `demo:checklist` and `checklist-pilot` example.
The workshop uses `devday:checklist` and `checklist-workshop`; its drafts do not
issue native typed finding-disposition receipts or apply canonical source edits.
Installed-host behavior and participant usefulness require their own evidence.

The [integration reference](api.md) explains the additive modules. The native editor, saved versions, authoring records and source-owner correction route remain authoritative. The cues never dispatch an assistant or apply a change.
